# זמנים חיים מהמסלול · תוכנת הגשר (dk-bridge)

תוכנה אחת במחשב הנייד של הצוות. היא מביאה את זמני ההקפות מהמסלול לאפליקציה, ומשם למסך המסלול ולאתר.

```
RentiX במחשב הראשי (פורט 50000)  ─┐
                                   ├→  dk-bridge במחשב הנייד  →  דף הצוות (?staff) באותו מחשב  →  מסכים ואתר
או: הדקודר AMB ישירות (COM / רשת) ─┘
```

- **קודם RentiX:** אם RentiX רץ, הגשר רק קורא ממנו את לוח הזמנים. הוא לא משנה בו כלום, ו-RentiX ממשיך לעבוד עם הדקודר כרגיל.
- **אחרת הדקודר ישירות:** רק אם אין RentiX, הגשר קורא את הדקודר AMB בעצמו. הוא בודק כל יציאת COM בכל מהירות, ואז את הרשת בפורטים 5403 ו-5100.
- מה שנמצא נשמר, ובהפעלה הבאה הוא מתחבר מיד.

## פקודה אחת (פעם אחת בלבד)

1. לחלץ את ה-zip במחשב הנייד, למשל ל-`C:\DanKarting`.
2. **לחיצה כפולה על `install.cmd`.** או להקליד ב-CMD:
   ```
   C:\DanKarting\dk-bridge\dk-bridge.exe install
   ```
3. לפתוח באותו מחשב את דף הצוות: `https://dankarting.github.io/dan-karting/?staff`

זהו. מעכשיו הגשר עולה לבד בכל פעם שהמחשב נדלק, ויש גם אייקון `DanKarting-bridge` על שולחן העבודה.
אם Windows מציג "Windows protected your PC": ללחוץ **More info** ואז **Run anyway**.
לביטול ההפעלה האוטומטית: `dk-bridge.exe uninstall`.

סימנים שהכול תקין:
- **בחלון הגשר:** `OK connected: RentiX ...` (או `decoder`), ואחר כך `Ready`.
- **בדף הצוות, בפס העליון:** `● RentiX מחובר` או `● דקודר AMB מחובר`. בזמן מקצה מופיעה בלשונית "חי" טבלת הזמנים מהמסלול.

**חשוב:** הגשר מחליף את `rentix-bridge.ps1`. לא להריץ את שניהם יחד, כי שניהם משתמשים באותה כתובת מקומית (`localhost:8787`).

## כשקוראים את הדקודר ישירות (בלי RentiX)

- **רק תוכנה אחת יכולה לפתוח את הדקודר.** כשהגשר קורא אותו ישירות, צריך לסגור תוכנות אחרות שמחזיקות את הדקודר.
- **מקצה:** מתחיל במעבר הראשון בקו אחרי דקה בלי מעברים, ונגמר כשהמסלול שקט שוב דקה. אפשר לשנות את זה ב-`heat_gap_sec`.
- **שיוך טרנספונדר לקארט (פעם אחת, ובכל החלפה):** הדקודר מכיר רק מספרי טרנספונדר.
  - בדף הצוות: הגדרות ← **שעון הקפות** ← להקליד ליד כל קארט את המספר שמודפס על הטרנספונדר שלו.
  - או הדרך הקלה: להעביר קארט על הקו. ברשימה **טרנספונדרים על המסלול בלי קארט** מופיע המספר שלו. מקלידים את מספר הקארט ולוחצים **שייך**.
  - עם RentiX לא צריך לשייך כלום: מספרי הקארטים והשמות מגיעים ממנו.

## בדיקות

- `test.cmd`: מראה בדיוק מה מגיע מ-RentiX או מהדקודר, ושומר עותק בתיקייה `logs`. כדאי להעביר קארט כמה הקפות ולהשוות לשעון עצר. אם זמני ההקפה מהדקודר יוצאים פי 4 גדולים מדי, לכתוב ב-`bridge.json`: `"rc2_time_unit_ms": 0.25`.
- `find.cmd`: מחפש את RentiX ואת הדקודר ברשת, ומציג את יציאות ה-COM.
- `simulator.cmd`: מקצה מדומה של 5 קארטים בדף הצוות, בלי חומרה. **לא בזמן מקצים אמיתיים.**

## הגדרות בקובץ bridge.json (Notepad)

| שדה | מה זה | ברירת מחדל |
|---|---|---|
| `source` | `auto` (קודם RentiX, אחר כך הדקודר) / `rentix` / `decoder` | `auto` |
| `rentix_host` / `rentix_port` | כתובת המחשב של RentiX | `192.168.0.1` / `50000` |
| `com_port` / `baud` | יציאת COM ומהירות של הדקודר. `auto` ו-`0` = מוצא לבד | `auto` / `0` |
| `decoder_host` / `decoder_port` | דקודר ברשת | ריק / `5403` |
| `min_lap_sec` | קריאה כפולה של אותו טרנספונדר מתחת לזמן הזה לא נספרת | `15` |
| `heat_gap_sec` | אחרי כמה שניות בלי מעברים המקצה נגמר | `60` |
| `rc2_time_unit_ms` | יחידת הזמן של דקודר RC2 | `1` |
| `local_port` | הכתובת המקומית שדף הצוות קורא | `8787` |

## חשוב לדעת

- דף הצוות קורא את הגשר רק **באותו מחשב** שבו הגשר רץ. משם הזמנים נשלחים לאתר הציבורי.
- עמודות המקטעים S1, S2 ו-S3 נשארות ריקות: יש לולאת זמן אחת בקו, והיא נותנת זמן הקפה בלבד.
- **מה עוד לא נבדק:** הקריאה מ-RentiX נבדקה מול RentiX מדומה. הקריאה הישירה מהדקודר (AMB RC2, P3 וטקסט `@`) נבנתה לפי תיעוד ציבורי. שום חלק עוד לא נבדק מול החומרה במסלול.
