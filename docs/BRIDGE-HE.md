# חיבור הדקודר AMB לאפליקציה · הוראות הפעלה

תוכנת הגשר (`dk-bridge.exe`) רצה במחשב הנייד שמחובר לדקודר.
היא קוראת כל מעבר של קארט בקו ושולחת אותו לאפליקציה בזמן אמת.
האפליקציה מחשבת ממנו הקפות, הקפה מהירה ומיקומים, ומציגה אותם במסך המסלול, בתוצאות ובאתר הציבורי.

```
דקודר AMB  →  כבל  →  מחשב נייד (dk-bridge)  →  אינטרנט  →  האפליקציה (?staff)  →  מסכים ואתר
```

## פקודה אחת: התקנה (פעם אחת בלבד)

1. **טבלאות בענן (פעם אחת):** ב-Supabase: SQL Editor ← New query ← להדביק את כל הקובץ `decoder-setup.sql` ← Run.
2. לחלץ את ה-zip במחשב הנייד, למשל ל-`C:\DanKarting`.
3. לסגור את חלון ה-CMD הישן.
4. **לחיצה כפולה על `install.cmd`.** או להקליד ב-CMD פקודה אחת:
   ```
   C:\DanKarting\dk-bridge\dk-bridge.exe install
   ```
   בפעם הראשונה היא שואלת את הסיסמה של משתמש הצוות `admin` (אותה סיסמה של כניסת הצוות באתר), ושומרת אותה.

זהו. מעכשיו:
- **הגשר מוצא את הדקודר לבד**: בודק כל יציאת COM בכל מהירות, ואם אין, מחפש ברשת (פורט 5403 ו-5100). מה שנמצא נשמר, ובהפעלה הבאה הוא מתחבר מיד.
- **הגשר עולה לבד בכל פעם שהמחשב נדלק**, ויש גם אייקון `DanKarting-bridge` על שולחן העבודה.
- **האפליקציה עוברת לבד לזמנים מהדקודר** ברגע שהגשר מחובר (אם לא בחרו ידנית "סימולציה" בהגדרות).
- נשאר רק לשייך פעם אחת טרנספונדר לכל קארט (למטה).

סימנים שהכול תקין בחלון: `OK signed in to the app`, `OK connected to decoder`, `Ready`. באפליקציה בפס העליון: "דקודר מחובר".
אם Windows מציג "Windows protected your PC": ללחוץ **More info** ואז **Run anyway**.
לביטול ההפעלה האוטומטית: `dk-bridge.exe uninstall`.

קבצים נוספים בתיקייה (לבדיקות בלבד): `test-decoder.cmd` (מראה מה הדקודר שולח, לא שולח לאפליקציה), `find-decoder.cmd`, `simulator.cmd`.

## חשוב: התוכנה הישנה (חלון ה-CMD שרץ היום)

לדקודר מתחברת בדרך כלל **תוכנה אחת בלבד** בכל רגע:
- **דקודר בכבל סריאלי / USB (יציאת COM):** רק תוכנה אחת יכולה לפתוח את היציאה. **לסגור את חלון ה-CMD הישן** לפני שמפעילים את הגשר. אם הוא פתוח, הגשר יכתוב:
  `COM3 is in use by another program. Close the old timing program`
- **דקודר ברשת (כבל רשת, פורט 5403):** חלק מהדקודרים מקבלים כמה חיבורים וחלק רק אחד. אם הגשר כותב
  `decoder closed the connection (another program may be connected to it)`, צריך לסגור את התוכנה הישנה.
- רוצים להשאיר גם את התוכנה הישנה? אפשר להגדיר בגשר `"relay_port": 5404`, והגשר יעביר את אותם נתונים בדיוק לכתובת `127.0.0.1` פורט `5404`. זה עובד רק אם בתוכנה הישנה אפשר לשנות לאיזו כתובת להתחבר.

**לפני הכול: לשלוח צילום מסך של חלון ה-CMD הישן.** ממנו רואים אם הדקודר מחובר ב-COM או ברשת, ובאיזו כתובת.

## בדיקה ראשונה באתר (10 דקות)

1. לסגור את התוכנה הישנה.
2. לחיצה כפולה על `test-decoder.cmd`, ולהעביר קארט על הקו.
   צריך להופיע: `OK  connected to decoder` ואחריו שורה לכל מעבר:
   `#1   15:04:12.345  transponder 1118533`
   אחרי הקפה שנייה של אותו קארט מופיע גם `lap 41.234`. **להשוות לשעון עצר.** אם הזמן יוצא פי 4 גדול מדי, לכתוב ב-`bridge.json`: `"rc2_time_unit_ms": 0.25`.
3. אם אין שורות מעברים: לשלוח את הקובץ מתיקייה `logs` ששמו מתחיל ב-`capture-`. הוא מכיל בדיוק מה שהדקודר שלח.

## כל יום

לא צריך לעשות כלום: מדליקים את המחשב, הגשר עולה לבד ומתחבר. להשאיר את החלון שלו פתוח.
(אם התוכנה הישנה עולה גם היא עם המחשב ותופסת את הדקודר, לסגור אותה.)
מתחילים מקצה כרגיל ב"התחלה". ההקפות נספרות מהרגע הזה.

אם האינטרנט נופל: הגשר שומר את המעברים ושולח אותם כשהחיבור חוזר. בנוסף כל מעבר נשמר במחשב בקובץ `logs\passings-תאריך.csv`.
אם הכבל לדקודר מתנתק: הגשר מנסה להתחבר שוב לבד כל כמה שניות.

## שיוך טרנספונדר לקארט (פעם אחת, ובכל החלפה)

כל קארט נושא טרנספונדר עם מספר. האפליקציה צריכה לדעת איזה מספר שייך לאיזה קארט:
- הגדרות ← שעון הקפות ← **קארט ← מספר טרנספונדר**: להקליד ליד כל קארט את המספר שמודפס על הטרנספונדר.
- או הדרך הקלה: להעביר קארט על הקו. ברשימה **מעברים אחרונים בקו** מופיע מספר הטרנספונדר עם "לא משויך". מקלידים את מספר הקארט ולוחצים **שייך**.
- במסך המסלול מופיעה אזהרה אם לקארט במקצה אין טרנספונדר, או אם עובר בקו טרנספונדר שלא שייך לאף נהג.

## בדיקה בלי דקודר (סימולטור)

לחיצה כפולה על `simulator.cmd`. הוא שולח מעברים מדומים של 8 קארטים, טרנספונדרים `1000001` עד `1000008`.
באפליקציה לשייך אותם לקארטים 1 עד 8, לבחור "דקודר AMB (אמיתי)", ולהתחיל מקצה. ההקפות יופיעו כאילו מהדקודר.
**לא להפעיל את הסימולטור בזמן מקצים אמיתיים.**

## הגדרות בקובץ bridge.json (Notepad)

| שדה | מה זה | ברירת מחדל |
|---|---|---|
| `connection` | `auto` / `serial` / `tcp` | `auto` (רשת אם יש כתובת, אחרת COM) |
| `com_port` | יציאת COM, למשל `COM3` | `auto` |
| `baud` | מהירות הכבל הסריאלי. `0` = מנסה לבד 9600 עד 115200 | `0` |
| `decoder_host` | כתובת הדקודר ברשת | ריק |
| `decoder_port` | פורט הדקודר ברשת | `5403` |
| `user` / `password` | משתמש הצוות של האפליקציה | `admin` |
| `rc2_time_unit_ms` | יחידת הזמן של דקודר RC2 | `1` |
| `relay_port` | להעביר את הנתונים גם לתוכנה אחרת | `0` (כבוי) |

## חשוב לדעת

- **שעון:** מומלץ שהאפליקציה (`?staff`) תרוץ על אותו מחשב נייד של הגשר, או על מכשיר עם שעה מדויקת (סנכרון אוטומטי של השעה דלוק). הפרש שעונים משפיע רק על ההקפה הראשונה.
- **עצור:** בזמן עצירה הזמן שנותר קופא, וזמן העצירה מתווסף לאורך המקצה. ההקפה שבה עצרו תהיה ארוכה.
- **מקטעים S1/S2/S3** לא מוצגים עם הדקודר: יש לולאה אחת בקו, והיא נותנת זמן הקפה בלבד.
- **פרוטוקולים נתמכים:** AMB RC2 / AMBrc (שורות `$...` בכבל סריאלי), AMB P3 (דקודרים חדשים יותר, ברשת בפורט 5403), ופורמט טקסט ישן (`@...`). הגשר מזהה לבד. זה נבנה לפי תיעוד ציבורי, ועוד לא נבדק על הדקודר שלכם, ולכן הבדיקה הראשונה למעלה חשובה.
